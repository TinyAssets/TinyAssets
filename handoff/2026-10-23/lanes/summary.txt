## Summary

Implements `openspec/changes/credential-vault-reshape/` (merged in #4622). This is not the closed #4611 design: there is no application-held master key and no offline escrow.

The founder decisions recorded 2026-10-11 match the spec. No conflict to flag.

- The root key is AWS KMS behind `TINYASSETS_VAULT_KMS_KEY_ARN`. The broker is the only process that reads the credential file.
- Each account KEK and each command-center DEK stays in the broker. Records and browser sessions are AES-256-GCM envelopes. Associated data binds account, command center, record id, and generation.
- A missing or unreachable KMS key fails closed (`key_service_unavailable`). One unopenable record asks for reconnect; the others still open. There is no plaintext fallback.
- CI uses `MemoryRootKey` when `TINYASSETS_VAULT_TEST_DOUBLE=1`. That double is refused when `TINYASSETS_ENV=production`.
