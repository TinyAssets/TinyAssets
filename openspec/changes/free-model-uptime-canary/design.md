## Context

This is a proposal, not implemented behavior. The Play closed test needs evidence that a free-model user's turn traverses the edge, auth, home resolution, serving admission, provider dispatch and reply delivery. Existing host health probes do not establish that.

Read `AGENTS.md`, the OpenSpec skill, PLAN's Operating Principles and the recent `recover-openrouter-key-handoff` change for house format. The current AGENTS file has no heading named "Spec-driven development"; its loop and PLAN's "Spec what is hard to reverse" principle apply. The existing `uptime-and-alarms` capability owns this addition. Its no-platform-model requirement (`openspec/specs/uptime-and-alarms/spec.md:865`) remains intact: only a dedicated account's private home holds a model connection, and ordinary deploy/public liveness gates never depend on it.

## Goals / Non-Goals

**Goals:** one served free-model request hourly, exact principal confinement, click-only credential enrollment, honest request accounting and an alarm after two consecutive failed samples throughout the test window.

**Non-goals:** changing user scheduling priority, replacing external uptime checks, running builds, proving every tool works, buying capacity, using a platform/founder model credential, or automatic daemon restart on a model failure. Monitoring prioritizes discovery and repair of the free-user path; it cannot guarantee OpenRouter availability.

## Decisions

### 1. Droplet runner and host-generated bearer

Choose a `tinyassets-free-model-canary.service` oneshot and hourly UTC timer installed by `deploy/install-host-uptime-services.sh` with its exact-source runtime/unit/timer manifests and convergence/rollback transaction. Follow the host unit pattern in `deploy/tinyassets-watchdog.service:24`: non-login service user, environment file, systemd-managed state directory, bounded execution, stdout/stderr journal. Use a dedicated run lock, a 120-second overall sample deadline and no restart-on-failure or immediate retry. Disable timer catch-up (`Persistent=false`); do not replay missed hours after downtime. Persist the UTC hour before dispatch and enforce a server-side one-turn-per-hour admission so process restarts, duplicate timer invocations and a leaked token cannot increase the budget. An uncertain admitted turn is never resubmitted.

Every sampled turn goes to exactly `https://tinyassets.io/mcp`, validates TLS and refuses redirects; neither localhost nor an internal hostname is a fallback. `.github/workflows/uptime-canary.yml` stays responsible for droplet-down detection, because a stopped droplet cannot execute this timer.

First deploy creates `TINYASSETS_FREE_MODEL_CANARY_TOKEN` from at least 32 cryptographically random bytes on the droplet, only if the canonical host-env assignment is absent. Under the existing host-mutation lock, validate the env file and reject duplicates, malformed or empty existing values rather than treating an unreadable file as absent. Pipe a freshly generated value to `deploy/install-tinyassets-env.sh set-once`; reuse existing valid values unchanged. Do not put a secret in command arguments, stdout, SSH results, workflow outputs, repository secrets, docs, backups or artifacts. Limit runtime exposure to the host runner and daemon authentication boundary; scrub it from provider/tool child environments. The bearer necessarily travels in the authorized TLS request through the public edge; "never leaves the droplet" means no exported/stored/operator copy, not a claim that bearer authentication transmits no credential.

Evidence and limitation: `deploy/install-tinyassets-env.sh:35` documents `set-once`, `:42` its absent/empty-or-identical semantics, and `:375`/`:445` the protected stdin staging discipline. `deploy/apply-daemon-env-remote.sh:1` documents droplet execution under the host-mutation lock; it is a feature-flag writer, not a secret generation API, and must not be widened into one. `docs/design-notes/2026-10-02-vault-key-escrow.md:26` records existing host-only session/billing keys; `docs/reference/environment-variables.md:81` documents session-key generation and host-env storage. Searches of deploy/, workflows and the escrow note found no executable generate-if-absent implementation for those keys in this checkout. The new generation step therefore reuses the evidenced atomic installation/locking pattern, not an alleged existing generator. The escrow note's proposed GitHub/offline copies are expressly not adopted for this regenerable canary bearer.

Deploy provisions one reserved account and private home idempotently, with a stable server-owned mapping and a designated real owner user ID permitted to enroll it. This mapping does not make that human a member/admin of the home and must not be derived from the first person to click. No personal home is reused. The runtime bearer cannot provision/recreate homes or activate connections. Do not create background tasks for this home. Fresh-host disaster recovery generates a new bearer locally and revokes the old one; no founder handles it.

### 2. Exact principal allowlist before dispatch

Model token comparison and early request refusal on `tinyassets/auth/wiki_canary.py:25` (constant-time comparison), `:42` (exact arguments), `:102` (call allowlist) and `:122` (whole-body classification), with middleware integration at `tinyassets/auth/middleware.py:1009`. Use a separate principal and request-local authority; never inherit wiki write permission or fall back to ordinary user authority after identifying this bearer.

For v1 the host uses direct JSON-RPC `tools/call` POSTs, so it needs no MCP discovery/session authority. Accept only a single object with exactly `jsonrpc`, `id`, `method`, `params`; `jsonrpc="2.0"`, bounded string ID, `method="tools/call"`, and params exactly `name`, `arguments`. Reject batches (including mixed batches), duplicate JSON keys, extra keys, notifications, initialize, tools/list, unknown methods and non-POST/non-MCP routes before any dispatch or side effect. If the served transport requires a handshake during implementation, resolve that with an explicit delta; do not silently inherit the wiki principal's broader protocol allowlist.

Allowed calls are:

| Name | Exact arguments | Authority/result |
|---|---|---|
| `converse` | `{"message":"Reply with the single word: ok","graph_id":"<reserved-home>"}` | One turn in the mapped canary home, at most once per UTC hour; server derives actor, model and policy. |
| `get_status` | `{}` | Server forces the mapped canary home and a canary-only projection, never fleet, other-home, credential or general transcript data. Includes readiness and the latest canary turn's nonsecret receipt/failure. |

The only failure-record read is that own-home status projection, correlated by the converse JSON-RPC ID mapped server-side to turn ID. No generic `read_graph`, `read_page` or transcript access is required. Reject caller-selected home, owner, model, request policy, read target or receipt ID in status. Bound status polling and response size. The converse argument spelling follows `tinyassets/universe_server.py:2918`; no caller-controlled model choice or consumer request is allowed.

The model itself receives no tool authority. Enforce the same restriction at internal dispatch: no nested reads/writes, connection calls, engine tools, callbacks or model-generated tool execution. A tool request is a failed sample, not a grant. Ordinary conversation persistence and receipts are necessary effects of `converse`, not general write authority. A leaked bearer can at most spend the canary home's hourly free-request allowance and observe its synthetic results; it cannot spend paid credit, obtain a key, alter bindings or reach another account. It can spoil/consume a sample, which is detectable and repaired by automated host-side rotation/revocation. Host/root compromise is outside the leaked-bearer boundary.

### 3. Click-only, one-time enrollment using existing PKCE

Choose an owner-only server enrollment endpoint, not a printed secret/nonce from deploy. The future `docs/host-actions.md` row contains the stable nonsecret URL `https://tinyassets.io/app/canary/connect`, with exactly this founder work: **1. Sign up at OpenRouter. 2. Open this link while signed in to TinyAssets. 3. Click Authorize.** The landing page clearly says it connects a dedicated uptime-canary account to free models only, not the founder's own home. Show that consent before leaving for the provider. No pasted key, secret store work, shell command or extra setup credential is required.

GET renders only an authenticated enrollment shell; it never mints a key or consumes consent (link scanners/prefetchers must be inert). The logged-in browser automatically calls a bounded same-origin JSON POST to mint/start enrollment using its session and S256 challenge. Only the configured owner may do this. Server generates a 256-bit nonce, stores its digest with purpose `free_model_canary_bind`, authorizing user ID, target canary account/home, installed acquisition preset digest, connection generation, browser challenge, callback origin and timestamps; expiry is 600 seconds, matching `tinyassets/connection_oauth/pkce.py:29`. The resulting one-time authorization URL is the ephemeral "connect the canary" link; the docs URL is only its owner-gated entry point. Minting again invalidates any earlier unfinished enrollment for that home. A connected home refuses new enrollment; an owner-visible reconnect ceremony for an explicitly disconnected/revoked binding gets a fresh nonce/generation.

Reuse the app's verifier generation, sessionStorage binding, provider redirect and callback handling (`tinyassets/onboarding/app.html:5187`), shared PKCE primitives/transactional flow store (`tinyassets/connection_oauth/pkce.py:67`), and existing hosted preset/key exchange (`tinyassets/onboarding/hosted_model_auth.py:164`, `:207`, `:247`). Keys remain server-side in the canary home's private vault; only code/PKCE material travels through the browser, as in the current flow. Use no-store/no-referrer responses, redact query/code/nonce logs, strip callback URL material promptly, and invalidate browser state on login change. The page exposes no manual-key fallback.

This requires a new **purpose-specific server enrollment grant**, not passing a canary home to an ordinary owner endpoint. Today `tinyassets/onboarding/model_connect.py:71` and `hosted_model_auth.py:140` require the authenticated user's current founder home; `model_bootstrap.py:58` explicitly returns an unanswered approval rather than enabling. Preserve those guards for all ordinary flows. Extract/reuse PKCE exchange and bootstrap building blocks behind an internal typed enrollment context with two separate identities: authorizing human and target reserved account. Never replace the ambient human identity with an unrestricted canary founder identity. Audit both identities and the one permitted bind.

At callback POST, verify the current signed-in designated owner, nonce purpose, expiry, PKCE, preset digest, origin, target mapping, account liveness and connection generation. Atomically transition issued to consumed before exchange; unauthorized attempts cannot consume it. Concurrent callbacks have one winner. The consumed receipt can be read by its owner but cannot redeem again. Before credential deposit and bind, recheck lifecycle/generation under the target's mutation guard so deletion, revocation or another connection cannot be overwritten. A durable operation receipt permits server-only completion/reconciliation of a partial deposit without replaying OAuth exchange; uncertain outcomes never cause automatic key re-creation. If unrecoverable, show a fresh owner-only ceremony, not a paste instruction.

The explicit enrollment page/provider Authorize ceremony consents to exactly one installed free-only binding. A server-only grant completes that binding using existing eligibility/grant validation, scoped to that target and operation; it is not a generic request-answer API or an ACL grant. The runtime canary bearer never receives this authority. No client field selects a home, owner, endpoint, paid policy or model. Restrict installed selection to zero-price OpenRouter models through existing preset/connection policy data, with no new vendor-specific compute implementation and no paid fallback. Do not silently auto-approve an ordinary founder bootstrap request.

Threat model: a leaked docs URL gives no authority; a leaked nonce additionally requires the designated owner's live session and correct PKCE verifier. Non-owner, stale/reused nonce, session switch, target substitution, preset change, replay and CSRF fail before exchange/deposit. XSS or compromise of the designated owner's session plus verifier can exercise this single bind, but cannot use it for arbitrary universe access. Root compromise is not solved by PKCE.

### 4. One model request, including learning and recovery paths

Hourly steady state is 24 inference requests/day against the lead's stated 50/day free cap (a planning assumption, not a provider guarantee). A normal founder turn with no `write_brain` invokes `_learn_from_turn` at `tinyassets/universe_intelligence.py:1586`; that calls `extract_learning` at `:1010`, which calls the provider with `_LEARNING_SYSTEM` at `:803`. `secondary_call=True` at `:823` prevents poisoning foreground cooldown but does **not** eliminate a second request. A one-word prompt alone therefore does not ensure one request. Deferred learning also needs exclusion; it must not accrue a lesson debt that a later tick pays.

Use trusted principal-scoped turn policy: skip learning extraction and debt scheduling, suppress tools, cap output to a small bounded value (32 tokens), and cap total inference dispatches to one at the actual provider-send boundary. Preserve ordinary real edge/auth/admission/router/HTTP inference execution. Choose one currently eligible free model before dispatch, then disable retry, fallback, malformed-reply repair, compaction inference and tool continuation for this turn. The coordinator normally has such recovery paths (`tinyassets/agent_turn_coordinator.py:869`, `:951`); skipping learning alone is insufficient. No caller flag can activate this policy for a different identity. Apply it across async continuation/reconciliation from a persisted trusted principal marker, not only a request ContextVar.

On zero-capacity/pre-send refusal the count is zero; on a sent failure it is one. Provider-send attempts and recorded rounds must reconcile for this restricted path; mismatch is a failed sample, never a fabricated count. Admission includes an idempotent hour/turn mapping, so a status poll or reconnect cannot initiate another turn. Catalogue/PKCE HTTPS requests are setup/control traffic, not inference calls, and are separately labelled if counted. Accepting 48/day was rejected: it leaves almost no headroom and learning has no value for the fixed synthetic prompt. Manual acceptance consumes that hour's slot rather than adding a 25th turn. No borrowed user key, shared free pool or paid route may satisfy the sample.

### 5. Receipts, readiness and alarm state

Store `/var/lib/tinyassets-free-model-canary/state.json`, following `scripts/watchdog.py:62` and its same-directory atomic replace at `:130`; use systemd StateDirectory mode 0750, state mode 0600 and the run lock. Keep the latest sample plus bounded incident state; the journal carries sample history under host retention. Schema version, UTC hour/time, request/turn IDs, phase (`awaiting_connection`, `active`, `disabled`), result (`pass`, `fail`, `skipped`), nullable `failure_code`, separate `probe_error`, nullable `requests`, `request_count_source`, `latency_ms`, answering `model`, attempted model if known, consecutive failures, activation generation and incident/notification state are nonsecret fields.

A served failure copies `turn_failure.code` and its `requests` unchanged (`tinyassets/universe_server.py:2757`, `tinyassets/conversation_failure.py`); success uses that exact turn's recorded round count and actual response model, never configured preference. Add a narrow receipt projection if success metadata is not currently returned; do not infer it from answer text or read the host data volume in lieu of the public path. The status projection can reconcile a timeout with the same turn only. If no authoritative receipt is available, `requests`/model are null (unknown), not zero; `failure_code` is null and `probe_error` names transport/auth/receipt failure. Pre-send zero is recorded only when proven. Keep an attempted model separate from a model that actually answered.

Measure monotonic latency from public converse dispatch to terminal reply or deadline, including public-edge/queue/provider delay; receipt reconciliation time is separate. Pass requires a terminal actual model reply whose stripped text is `ok`, no structured failure, one request, verified free policy and nonempty answering model. Cached/static status, partial output, multiple requests, unknown accounting or wrong content cannot pass.

Before the first successful connection bind the unit is **dark**: no converse/provider request, no failure streak or outage alarm; record `skipped/awaiting_connection`, never green. Read local activation metadata only to avoid attempting an unconfigured turn; it is not liveness evidence. Activation is durable. After activation, missing/revoked keys or a missing home are failures and must never return to silent initial-dark mode. `get_status` exposes readiness without a key. A missing home is not auto-created by the probe. Corrupt/unwritable state is an operational fault logged/alarmed through the host channel; never silently reset an active incident or dispatch when duplicate suppression is unknowable.

At the second consecutive failed hourly sample append a redacted `FREE_MODEL_CANARY_FAILED` event to the same host watchdog alarm sink, `/var/log/tinyassets/uptime_alarms.log` (honor `TINYASSETS_WATCHDOG_ALARM_LOG`), and journal it. Evidence: `scripts/watchdog.py:89`, `:110`, `:402`; unit log-directory setup is `deploy/tinyassets-watchdog.service:35`. Persist a pending incident before publishing; retry failed notification delivery without spending another model request. Deduplicate using incident ID; ongoing failures update state/journal, and the first passing sample resets the streak and emits one recovery. A failure followed by a pass does not alarm. Do not restart the daemon for quota/auth/model failures. The shared file/journal is an existing local alarm channel, not proof of a delivered external page.

GitHub issues are **optional best effort**: reuse an already-installed host `GH_TOKEN` only if it has issue permission for TinyAssets/TinyAssets. `scripts/watchdog.py:163` already posts issues using this token and explicitly skips when absent; the escrow inventory `:38` records a host token but does not prove its current permissions. On threshold, create one issue with a stable incident marker, persist its number, update that issue on further failures and close on recovery; reconcile by marker after an uncertain POST, never blindly duplicate. Use bounded redacted API errors and retry independently of model dispatch. If token absent, inaccessible or insufficient, record `issue_delivery=unavailable`: **the host channel alone is the alarm**. Do not create a PAT, restore a retired push credential, assume Actions' `GITHUB_TOKEN` exists on the host, or ask the founder to handle a secret.

## Alternatives Considered

- **(A) WorkOS refresh-token canary from GitHub Actions — rejected.** Refresh tokens rotate, so a static CI secret can go stale; provisioning/recovering it introduces founder secret handling. It also exports authentication material off-host. Existing external liveness checks remain in Actions without adding this identity flow.
- **(B) Droplet timer with constrained host bearer — selected.** Stable host-local provisioning, no founder secret steps, real public edge; external uptime covers the timer's host failure.
- Generic founder/admin token, wiki write principal, or connecting through the runtime bearer — rejected for excess authority.
- A host command printing a live nonce into a committed docs row — rejected in favor of the stable owner-only minting URL, avoiding expiring URLs in git and secret-bearing deploy output.
- Reusing ordinary OAuth by substituting another home ID — rejected because current-home checks are deliberate security boundaries. Use the explicit one-bind enrollment context.
- Localhost/model-only probes, stub replies or two calls per turn — rejected because they miss the requested path or waste free capacity.
- New GitHub credential or mandatory issue delivery — rejected; the existing host alarm channel works without that prerequisite.

## Risks / Trade-offs

| Failure | Behavior |
|---|---|
| OpenRouter daily cap/rate limit/overload | Preserve the served structured code (`provider_daily_quota`, `provider_rate_limited` or `provider_overloaded`, as emitted; `tinyassets/conversation_failure.py:50`), actual requests and latency; no retry/paid fallback; two failures alarm. Never invent a code from prose. |
| Key revoked after activation | Served auth failure remains active/red; owner-only fresh click ceremony can reconnect. No secret paste or silent dark mode. |
| Canary home absent/deleted | Fail with a separate probe error or exact served failure if available, no home recreation and no other-home fallback. Deploy/operator automation reconciles the reserved mapping. |
| Edge/TLS/DNS unavailable | Failed public sample with unknown count unless receipt proves it; droplet-down coverage remains external. |
| Timeout after upstream send | Do not repeat converse; bounded status-only reconciliation, then alarm using honest unknowns if needed. |
| Free model disappears or returns tools/wrong text | Fail that sample; next hour can select another eligible free model. A one-word probe intentionally does not validate builds. |
| Owner abandons/loses PKCE browser state | Expire and require a fresh owner-only link ceremony; no replay or fallback to pasted key. |
| State/alarm persistence failure | Journal operational error and retry delivery; never claim passing monitoring or reset a known failure streak. |

## Migration Plan

Ship server enrollment/principal/receipt support and host provisioning together. Provision bearer and private home without a provider key, install timer dark, and add the three-step `docs/host-actions.md` row with the stable enrollment URL. Observe that no model call occurs before the owner authorizes. After bind, run one scheduled-slot live public turn, inspect receipt and alarm-path evidence, then assert deployed SHA and sync the delta. Implementation includes focused tests; this drafting session runs no tests, only OpenSpec validation.

Rollback disables the new timer and principal/enrollment routes and invalidates outstanding nonces; preserve private connection data and receipts for investigation. Never weaken other probes or delete the owner's connection as a rollback side effect. Ending the test uses an explicit disabled state and disabled timer, not loss of credentials interpreted as success.
