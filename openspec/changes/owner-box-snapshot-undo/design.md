## Context

Binding basis: `../owner-daemon-in-box/research.md`, design T1-T10, C1/C2 and C14/C15; registry N6/S27. One opaque volume holds all owner state; the shared layer knows volume/snapshot IDs, never content paths. N6 adds callers to that lifecycle, not another snapshot implementation.

## Goals / Non-Goals

Offer coherent owner-confirmed undo before agent execution. No per-tool snapshot engine, selective file restore, memory/process checkpoint, external-service rollback or platform-authority rewind.

## Decisions

1. **Trigger: one per turn.** The in-box scheduler persists the queued turn, closes work admission, drains current work and requests the ordinary C2 graceful sleep/snapshot. This precedes all agent execution, including scheduled/background turns and shell actions whose effects cannot be classified ahead of time. A turn's tools share its checkpoint; there is no per-tool stop. Only an unchanged, still-detached volume's latest verified snapshot can be reused. UI reads do not trigger checkpoints.
2. **Durable handoff.** The queued turn and its checkpoint association are box-local. The existing lifecycle intent carries only an opaque checkpoint correlation and snapshot reference, never turn payload/history. Stop, flush, exit, clean unmount/detach, immutable copy, upload/readback verification and publication follow C2/C15. The turn resumes once after verification and ordinary wake; no user or scheduled wake may admit that queued turn early. Retries use the same intent; checkpoint failure blocks execution visibly. This handshake must survive restart without a checkpoint loop or a lost turn.
3. **Retention and cost.** Use C2's single catalog: latest seven verified snapshots across backup and undo, plus references pinned by supported platform recovery points and the current turn's checkpoint. Keep the latest pre-turn checkpoint available until replaced by the next verified pre-turn checkpoint; subsequent sleep snapshots must not evict it. App shows only retained points. No separate undo archive or arbitrary time guarantee. The 5 GiB free tier is the live-volume allowance; snapshots are platform backup overhead, not a silent reduction of that allowance. Seven full incompressible images approach 35 GiB per owner, plus recovery pins, one retained pre-turn pin if outside seven, and transient copies. Sparse files/reflinks/compression are savings, not a capacity guarantee. Reuse existing pin/prune operations; never delete a referenced point to make room. Insufficient headroom blocks the turn with a storage error.
4. **Whole-volume restore.** Undo replaces files, owner databases, history, skills, packages and schedule state together. The confirmation states that later chat/history and local edits disappear and external sends/purchases/publications do not reverse. Platform identity, admission, credentials, billing, spending and N5 policy remain current. Owner content interpretation and database validation occur only inside the restored box.
5. **Owner action, safe stop.** App lists snapshot time/scope and requires confirmation bound to snapshot ID and current volume generation. An agent may raise an existing approval request but cannot confirm or restore. Close work admission, let the running turn drain (or use the existing owner cancellation path and wait for exit), then invoke ordinary lifecycle restore. Never swap a mounted volume or force a partial turn snapshot. Stale confirmation, missing snapshot, erased/suspended admission or changed generation refuses. C2 commits the new generation before restart; interrupted restore resumes from the existing intent.
6. **Resume after rewind.** Restored-generation startup validates DBs in-box, pauses queued turns/schedules and invalidates restored pending approvals before reopening owner work. No restored queued turn or overdue schedule executes until the owner explicitly resumes it; new operation IDs use the new generation. Earlier-generation operations and N5 grants refuse. Record the undo result in the restored box after validation; do not keep a shared history copy. No automatic redo snapshot is promised.

## Shared surface and proof

Shared edits are confined to the existing `tinyassets/broker/volume_lifecycle.py` lifecycle call and its `owner_volumes` intent/pin arguments: checkpoint completion and protected restore invocation. The same `boxes/volumes.py` opaque executor and off-host format serve N6 and S27. No additional snapshot engine, shared scheduler, router logic, waker clock, filesystem scanner or host path to owner data. Turn/approval/app logic stays in-box.

Planned registry guard **`box-snapshot`**: extend `tests/test_owner_volume_structure.py` to prove undo and S27 call the same lifecycle/executor; extend `tests/test_owner_volume_lifecycle.py` for checkpoint-before-execution, interrupted handoff/restore, retention pins, concurrent wake, deletion and quota failure. Extend `tests/test_owner_volumes_proof.py` on the disposable Linux mount venue for files+DB+history restoration, complete detach and no shared traversal. In-box acceptance proves owner confirmation, running-turn drain, paused restored queues, old operation refusal and unchanged platform authority. A skip is not proof.

## Risks / Trade-offs and implementation gate

Every turn pays stop/restart plus compression, upload and verification latency. Measure sparse and near-full 5 GiB volumes: stop/snapshot/upload/readback latency and peak local/remote bytes; do not claim instant undo or rely on compression. Implementation waits on C6 registry close-out, C1/C2/S27 single-owner recovery proof and a measured fit within the approved storage budget. If frequent checkpoints do not fit, bring a trigger/retention revision for decision before implementation; no new spending is authorized here. Rollout reuses existing images/catalog; rollback can hide Undo but must preserve recovery references. This PR changes specs only; implementation tasks remain unchecked and as-built specs remain unsynced.
