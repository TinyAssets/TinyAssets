# Proposal

## Why
A second account cannot discover already-public component systems in a file-package-only picker. The empty-catalogue blank screen also hides browsing and lets its only dismissal erase every creation option.

## What Changes
- Keep Build your own and Try someone else's accessible in the blank screen and trusted own/shared switcher, including empty, failed and loading catalogues.
- Remove only the blank offer's No thanks action; retain notification opt-out.
- List supported public component systems separately from file packages and copy them only through an explicit owner-confirmed, pinned component-only plan.
- Reuse private workflow remix, additive screen installation, paused automation creation and declared workflow-reference remapping; never invent package bytes, import private files or rewrite script text.

## Capabilities
### New Capabilities
- `command-center-discovery`: persistent navigation and owner-confirmed copying of already-public component designs. Related earlier package/harness requirements remain in existing change deltas; no baseline capability currently owns this picker.
### Modified Capabilities
None.

## Impact
command_center_picker.py, package_requests.py routing, a dedicated system-copy module, the existing pinned request's try eligibility, AppUI picker/paint/open methods, mirrors and focused tests. No app.html changes, real-account writes, republishing, resets, new execution permission or changes to ongoing mobile/placement code. The metadata prerequisite remains separately checkpointed.
