# Tasks — channel-agnostic-outbound

Design-gate change. No task here is started until the opposite-provider (Codex) review returns
`approve`/`adapt` and the founder confirms the ownership split + coordinated sync with
`outbound-boundary-layer`. The execution seam is the EXISTING spawned credential-blind broker
(`storage/outbound_connections.py`); there is no in-process secret-resolution path. Each channel
migration is proven by a semantic equivalence matrix (design.md D6), backfills its ledger
connection, and flips atomically — never two credential paths live, never a fall-through to
another credential source.

## 3. GitHub pull-request

**Shape analysis (2026-08-20).** GitHub is already the furthest-migrated channel: `github_pull_request` is credential-blind + broker-dispatched TODAY via `_ProductionGitHubNetworkDriver` (which calls `github_pr._prepare_scoped_github_commit` / `_publish_scoped_github_pull_request` with the child-resolved token). SHAPE FINDING (real): GitHub is a MULTI-CALL TRANSACTION (blobs→tree→commit→ref→PR), which the general primitive's ONE-request-per-dispatch `http` model does not naturally express — the current pattern (a github-typed handler running the whole sequence inside the child under one grant) is the correct shape and the design already keeps it. What remains to migrate is EGRESS unification: routing `github_pr`'s internal `urlopen` calls through the general SSRF-hardened driver + a github allowlist (all `api.github.com` PR-flow endpoints). That is a large, careful refactor of a 2429-line orchestrator, deferred behind the shape review — NOT forced into this first draft. Twitter+Slack (single-call) are the primitive's direct target; GitHub validates that multi-call transactional channels keep a channel-specific in-child orchestrator over the shared credential/egress substrate.

**SLICE 1 LANDED (2026-08-20, founder chose the full refactor over the defer, commit 0699740a, DARK).** Nine credential-blind `github_*` request builders + `GITHUB_ALLOWED_ENDPOINTS` (parsed through the storage validator) + `GITHUB_VIA_CONNECTION_FLAG = "TINYASSETS_GITHUB_OUTBOUND_VIA_CONNECTION"` in `outbound_channel_adapter.py`, proven byte-identical to `github_pr`'s real construction (POST bodies pre-encoded default-`json.dumps` to match, not the driver's compact form) by 8 differential tests through the real `_SsrfHardenedHttpDriver`. `github_pr.py` untouched. **SHAPE FINDING (real, drives slice 2A):** the `OutboundEndpoint` template matches a FIXED segment count, so it REFUSES github's multi-segment URL tails — subdir contents-reads (`contents/{path}` safe="/") and slash-bearing branch refs (`git/ref/heads/{branch}`, e.g. `feat/x`). Wire requests are byte-identical but the allowlist refuses them (`test_github_contents_subdir_path_refused_by_allowlist`); since TinyAssets PR branches carry slashes, the template model must gain a `{path:rest}` multi-segment tail (still rejecting `%2e`/`%5c`/dot-segments/control-bytes/encoded traversal, exact-host, no escape above `/repos/{owner}/{repo}/`) BEFORE the flip. Codex security review of slice 1 + the exact rest-tail contract is in flight before slice 2.
