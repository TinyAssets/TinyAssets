## Context

ADR-017 makes editable files the default knowledge authority; ADR-018 requires one portable export. Today the OKF bundle is seed-only, `memory/`, `retrieval/`, `knowledge/` and `daemon_brain.py` own later state, and `wiki/okf_export.py` has no owner action. This change follows `owner-daemon-in-box/research.md` and its binding T1–T10 table: owner logic and files live in the box; the router forwards, the broker holds credentials and egress policy, and the waker holds only wake time. No shared service obtains a host path into an owner volume.

## Goals / Non-Goals

**Goals:** One canonical file tree per owner, default OKF layout, disposable in-box indexes, one complete export action, and deletion of second canonical stores.

**Non-Goals:** A new brain editor, provider-specific runtime, shared knowledge service, or extension of the C6 one-shot migration. Users may replace the default file organization while retaining the source/index split.

## Decisions

1. **Files win.** The owner's box owns reads, edits, conflict handling and indexing. Markdown with frontmatter, links and root `okf_version` is the seeded form. Index rows carry source identity and revision; a missing, corrupt or stale index is rebuilt from files. A failed file write does not publish a newer index. Existing SQLite/vector APIs may remain as in-box derived readers only until their consumers move. Alternative rejected: treating the current database and files as coequal authorities, which preserves S17's drift.
2. **Convert after C6, once per owner.** Take one verified owner-volume snapshot and stop that box's writes across knowledge and memory. Inventory every table and file in each store being retired, recording source counts and stable row IDs. Classify every row as converted to an owner file, moved to a named box-local operational store, or derived with a named file rebuild source. Convert all lifecycle states, including candidate, rejected and superseded mini-brain entries, review/promotion history, replay results and cost events; retain their provenance and status in files or box-local operational history. Convert graph facts without a file source to files. Compare per-source input and output counts, IDs, content hashes and a representative retrieval set; report any unsupported field or row and refuse cutover on loss or unclassified data. Then switch readers and writers together. On failure, keep that owner's prior serving version and restore its snapshot if needed. No shared host-side walk or repeat of C6 migration.
3. **One command-center export door.** An authenticated owner request reaches an in-box export assembler through the router. The same action serves UI and agent invocation and returns a downloadable folder/archive. It takes a consistent file snapshot, includes harness, roster, rules, workspace, wiki/brain, workflows, schedules, selected memory and UI layouts, plus a versioned **export manifest** defining paths, hashes and format version, README, local runner, license placeholder, `.gitignore` and `.env.example`. The runner uses the four tools plus `ta` and a user-supplied model connection; it needs no platform account. The box excludes credentials and private broker custody; the broker never packages owner files. The existing `tinyassets/boxes/boxd.py::import_bundle` consumes this manifest and archive for sharing/import. Delete `tinyassets/wiki/okf_export.py` as a separate door. Keep `conversation_custody.export_conversation` and `storage/conversation_custody.export_thread` for single-thread custody transfer, `refs/tiny/export` in `workspace_git.py`, `workspace_remote_cell.py` and `boxes/node_runner.py` for Git workspace transport, and `publish_requests.export_ui_component` for one published UI component; none offers a full command-center download.

## Risks / Trade-offs

- **Incomplete conversion or concurrent edit** → Serialize per-owner conversion with box writes, verify content, and retain that owner's pre-slice snapshot until acceptance.
- **Index drift or cost of rebuild** → Version indexes by file revision, rebuild in-box, and treat index failure as a visible degraded read rather than silently preferring stale data.
- **Export leak or incomplete folder** → Allowlist bundle entries, exclude credential material, validate the manifest, and test local run and import from the exact produced archive.

## Migration Plan

Ship K1 through K4 after C6's owner-volume cutover. Roll back a failing slice by restoring only the affected owner's verified pre-slice snapshot and its previous serving version. Do not restore shared platform state. Close S17 only when its registry guard proves all four exit checks together and the obsolete canonical paths are absent.
