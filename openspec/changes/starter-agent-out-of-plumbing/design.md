## Goals / Non-Goals

Move starter policy to editable files using the existing skill mechanism, with no special starter runtime. Owners can replace instructions, persona/soul, skills, rules, extensions and the main agent within existing authority. Retain reliable remembering and time context with small resident hooks. This slice does not implement D6 discovery, D7 learning retirement or D10 seed storage.

### Resident guidance alongside custom instructions

The published bundle puts every moved resident hook listed above in `starter/hooks.md`, separate from `AGENTS.md`; it does not duplicate these hooks in stock `AGENTS.md`. This newly introduced path and the five `skills/starter-*/SKILL.md` paths are installed by D10's never-installed/exclusive-create rules even when `AGENTS.md` is customized, empty, linked, unreadable or previously deleted. A missing historical `AGENTS.md` remains deleted. Existing collisions at the new paths are preserved under the same D10 rules, never overwritten.

Generic ordered instruction-file loading reads the selected agent's actual `starter/hooks.md` bytes before its `AGENTS.md` bytes on every authorized owner turn, independently of whether `AGENTS.md` can be read or a skill is loaded. Each block carries its source path; explicit owner instructions take precedence over starter guidance. The generic skill index lists the five installed skills without any amendment to `AGENTS.md`. This restores the former plumbing behavior for a customized center without merging into its text or reintroducing default-text substitution. The file contains the resident memory, continuity, input-method, incomplete-onboarding, harness, grounding-current and response-priority hooks in the map; recipes remain on demand.

The version-keyed owner notice names added hooks/skills and preserved files: "Your AGENTS.md was kept unchanged. Starter guidance previously supplied by the runtime now loads from starter/hooks.md alongside it; starter skills are available in the skill index. You can edit or delete these files, or Undo these additions." It separately names any collided, unreadable or deleted hook/skill path, the guidance unavailable as a result, and the offered candidate; it never reports those paths as successfully installed. Existing custom skill precedence is unchanged. Empty/linked/unreadable legacy instructions get D10's specific former-defaults explanation as well.

The memory trigger is resident because an optional-load decision risks the observed recite-without-write regression. Later editing, emptying, deleting or Undoing `starter/hooks.md` is an owner choice; no loader fallback or future seed upgrade reinstates it. Unreadable/linked hooks are skipped with a visible read failure. Selecting a replacement main agent loads that agent's instruction files, never silently appends the old main's hooks. Clock data remains available within the founder's authorized context. Default and preserved-custom-AGENTS fixtures both face the full memory matrix below; the tiny demo is additional evidence.

Verify recipes and permissions rather than inventing commands. Core + four schemas <1,000 tokens is a **D6 precondition**, not this slice's acceptance criterion. It lands before activation; this slice does not rebuild it.
3. **This change alone owns cutover integration and the all-center/dormant-center proof (task 2.3).** At one coordinated release boundary, use the completed seed-lifecycle mechanism and switch **every** center to generic file/skill loading. Unattended and dormant centers are included. Stock/seed-identical files upgrade automatically; customized AGENTS.md remains untouched while new hooks/skills arrive alongside it with the notice above. A collision or missing owner response never holds runtime activation. A dormant center's first turn resumes the safe transaction and uses only the new renderer. Remove the old policy renderer and read_operating_instructions reseed/fallback in that release; no grace period, compatibility mode or review wait. Record actual cutoff UTC time and SHA. Seed-lifecycle owns the transaction API and its recovery tests, not renderer wiring or a second cutover proof.
4. D6 must preserve reachability during an intermediate release, or coordinate old-handle removal with this single global cutover. Never remove a working handle before its replacement recipe works. File Undo stays on the new runtime.
5. Extraction retirement and unresolved source migration stay solely in parent D7, after IDs/history/Undo and no-regression proof. They do not delay renderer cutover, and are not enabled/disabled per center by file adoption. Parent D6, D7, D10 and appendix contradictions are reconciled now. Sync each capability from its sole owning change after implementation.

## Risks / Trade-offs and Proof

### Cost

Extend tests/test_converse_turn_cost.py to measure every serialized request with pinned fixtures, tokenizer/model, adapter version, SHAs and generation settings. Record baseline, D6-only and D6 plus this slice **separately for each supported adapter**, explicitly HTTP, Codex and Claude where supported. Compare the same memory/extraction state across D6-only and final so D7 cannot subsidize results.

Separate core + schemas, starter instructions/index/hooks, owner grounding, history, loaded skills/tool results, extraction requests, input/output totals and round trips. Report cold-start skill loads and follow-up reuse; no cache discounts or user-content truncation. D6 schema savings and the non-resident handbook never count here.

Acceptance for this slice, for each adapter: default starter instructions/index/hooks <=1,000 tokens; non-tool resident default overhead >=50% below D6-only on identical fixtures; **full-task total tokens for each fixture task <= its D6-only result**, including all skill loads and model calls. Record calls, including added skill-load round trips. Fixtures cover fact teaching/recall, access/GitHub, onboarding/resume, time-relative scheduling and workspace work. Rework loading or seeds if targets fail; do not claim a resident win that raises total cost. Lower ratchets to measured passing counts; leave schema ratchets with D6. All figures remain unmeasured targets here.

### Reliability

For **every supported model family and each of two fixture classes** (stock AGENTS.md and a preserved customized AGENTS.md that contains none of the moved hooks), run N>=10 paired natural "teach a fact" trials against baseline **with extraction on**, holding each fixture's owner bytes/settings constant. The custom fixture receives hooks/skills alongside its unchanged AGENTS.md, with no owner acceptance step. Score verified durable write rate immediately after teaching and correct recall rate in a later cross-surface turn separately. Both rates must be **no worse than baseline in every family/fixture cell**; publish numerator/denominator and traces per cell, never pool away a regression. Include negative controls for jokes, hypotheticals, secrets and write failures. Run this entire two-fixture matrix for this prompt move and again in D7 with extraction off before removal; a single successful demo is insufficient.

Clock cases include known timezone without a redundant question, unknown timezone without guessing, changed timezone, local midnight/day rollover and cross-surface continuation. Private clock/brain/work/ask data must remain absent for unauthorized tiers. Verify empty/deleted/linked/unreadable AGENTS.md never triggers fallback text or writes to that file, while separately installed hook bytes still load. Verify hook edits/deletion/Undo, collision notices and replacement-main selection. On tool-less turns with default, customized, blank and replacement-agent instructions, assert zero available tools and the factual no-tools line even with hooks absent; on tool-enabled turns assert that line is absent. Count the retained factual line in cost evidence.

Live proof on customized tiny, without naming skills: teach/recall a benign fact across surfaces; request access and observe the correct real request without repeated key asks; use a known-timezone request without reasking. On a disposable starter agent, partially complete onboarding, resume elsewhere, and verify missing-field-only questions, persisted answers and governed rules/cadence proposals. Tiny must not restart onboarding. Record file diffs, skill traces, request receipts, per-adapter tokens/calls and asserted deployed SHA. These are future implementation proofs, not claims made by this revision.
