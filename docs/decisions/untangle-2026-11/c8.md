# C8 as built (2026-11-14)

C8 is lane C's PR for item 3 of the cross-PR re-check (2026-11-14): the object-shape checks were copied a fifth and sixth time after #5531's "no fourth `plain`", because `contract/src/checks.ts:6` imported `./refusal` with no extension, and Node's type stripping, which runs the deploy kit, resolves a specifier only as written.

1. **The rule is "every contract module loads in Node as it is", held by running it.** `contract/guards/node.test.ts` imports each `contract/src` module under `node --experimental-strip-types`, the way the kit runs, and names every one that fails. Before this PR 22 of the 44 failed, each on a sibling imported without `.ts`. A syntax check for the extension would hold the cause; loading the modules holds the effect too, so it also catches syntax that Node can't strip and anything else that stops a module loading in Node. No guard did this before. `deploy/guards/deploy.test.ts`'s keyring run loads the kit's own closure, and now reaches `checks.ts` through `deploy/operator.ts`, but nothing loaded the contract as a whole.
2. **All 75 extensionless imports in `contract/src` take `.ts`, in every lane's files.** The guard needs every module to load, and each change is just the specifier, so a conflict with another lane's PR is a one-token merge. An `owed` list of the 58 import lines outside lane C's files for the guard would be more process than the fix, and `ratchet` takes only `B<n>` fixes.
3. **`checks.ts` is the one home, and its tests are `object`, `keyed` and `whole`:**
   - `object` is policy-document's stricter test: a JSON object, so not an array, not null and no class instance (its prototype is `Object.prototype` or null). Every caller holds JSON or structured-cloned data, so none sees a difference. `canonical` depended on the stricter test: under the loose one a `Date` became `{}`. The name stays `object`, the home's own: four gateway and sources files call it about 30 times, so renaming them to the copies' `plain` would have touched lane V for no gain. `acts.ts`'s `object as plain` alias goes, and its two sorted-string key checks are `keyed`.
   - `keyed(value, required, optional = [])`: a JSON object with every `required` key, any `optional` one and no other, in any order. It replaces the sorted, comma-joined string. That string was a hidden rule: an unsorted one never matched, and gave no sign. It folds `exactly` (operator-message), `keys` (policy-document), control's `plain(value, keys)`, binding's `fields` and parseControl's required-and-optional check, and every inline `Object.keys(x).sort().join() === "…"` in the files it touches. `shape` is now `keyed` or `invalid_source`, and `count` is `whole` or `invalid_source`.
   - `whole(value, min, max?)` replaces operator-message's and policy-document's `whole`, control's `positive`, binding's inline test (its refusing wrapper is renamed `integer`), and `bounded`'s range check.
4. **The six copies are gone:** `operator-message.ts` (`plain`, `whole`, `exactly`), `deploy/operator.ts` (`plain`), `doors.ts` (`plain`), `control.ts` (`plain`, `positive`), and policy-document's exported `plain`, `keys` and `whole`. Their importers, `owner/src/policy.ts` and `owner/src/grants.ts`, import `checks.ts`. Item 3 assigned these files to lane C, though they belong to lanes O, X and R.
