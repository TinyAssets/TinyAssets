# Vendor wake pages as built (2026-11-18)

Reviewed 2026-11-18 for d3 §C8. The public pages resolve which protocol each product exposes. Delivery to a real owner's agent and the OAuth redirects remain live checks before enabling sign-in.

- **ChatGPT.** A plugin can advertise events with Streamable HTTP initialization or MCP 2.0 discovery. Web Work chats, desktop Cloud Work chats and dots can subscribe. The help article lists eligible plans and workspace admin controls for built-in event-triggered tasks. Its account-wide run caps do not establish that a custom plugin works on each plan. Keep the custom-plugin subscription and wake check per tier. [MCP Events](https://developers.openai.com/plugins/build/mcp-events) · [Tasks](https://help.openai.com/en/articles/10291617)
- **Grok Bot.** Its owner-provided bearer credential belongs to its routine. Only HTTP 200 confirms that the routine started. The public guide gives no fixed callback host. A desktop owner can enter a remote HTTPS server in Connect apps. TinyAssets still needs a verified OAuth redirect before the Grok dynamic client can register. [Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations) · [Apps](https://docs.x.ai/grok-bot/computer-and-apps.md)
- **Consumer Grok.** Its automation uses a Standard Webhooks signing secret and returns 202 for acceptance. The app and doorbell records identify Grok Bot. The consumer product would need its own registration and delivery evidence before it could be offered. [Webhook triggers](https://docs.x.ai/grok/automations/webhooks)
- **Meta Muse.** Its own schedule can prompt a digest read. Meta now documents Muse Mail and accepts owner instructions from a verified personal email account. The connector guidelines describe Muse calling an integration. None of these sources gives a third-party connector a push endpoint. [Scheduled tasks](https://www.meta.com/help/superintelligence/1484325780075655/) · [Muse Mail](https://www.meta.com/help/superintelligence/1149305437517250/) · [Connector guidelines](https://platform.muse.ai/docs)

The transport records and registration policy stay as tested. The owner doorbell currently counts every 2xx as sent. A separate owner change is owed to count only 200 for Grok Bot, preserve the raw response for diagnosis, and continue to accept the documented MCP success range. A successful HTTP response establishes vendor acceptance, never completion of the user's task.
