# O2 as built (2026-11-15)

B4's owner half (d2 B4; d3 §K4; `b23_research.md`, B4's question). The table split and the generated `OwnerDoors` are the contract half, `untangle/o2b` (item 9).

1. **The door table defines the object's methods at module load.** `OwnerDO`'s `static {}` block walks `doorTable()` and defines each row's method on the prototype (`Object.defineProperty`, not writable), so `#call` and the object's state stay private. A row's method takes its binding unless its caller is `none`, and its request unless it takes none. It hands its row and handler to the one runner, `#call`, which replaces `#run` and `#units`: the row's gate picks a unit of the gate, or the door that a `units` handler checks in each unit it makes. A row that takes no request is handed none, whatever came, as the hand methods did. The 134 hand methods and their triple spelling of each name are gone (1,098 lines).
2. **Reserved names are refused at module load.** `RPC_RESERVED` (`contract/src/doors.ts`) holds Cloudflare's reserved and disallowed RPC names. The loop throws on one, or on a name the class already has (`fetch`, `alarm`, anything on the chain). `doorProblems` refuses one too. The ci gate (`ci/gate.ts` `gate()`) refuses one where the gate is made, so the gate Worker's own copy of the list goes (d3 §M6, the T0 review's nit for T1). The worker keeps only its "already defined" check, since it is one transpiled module and cannot import the contract.
3. **The generator reads the table one way and writes the typed handler map.** `contract/requests.ts` reads `doorTable()`; its own `tableRows()` goes. Beside `contract/src/requests.ts` it writes `owner/src/door-map.ts`:
   - `DoorRows`: each door's module, caller and gate as literal types;
   - `DoorMethods<H>`: each door as a method signature, its request and answer those of its handler in `H` (`RequestIn`, `AnswerIn`), and its doc its row's tool description.

   `interface OwnerDO extends DoorMethods<typeof HANDLERS> {}` types the stub. Owner tests and the doors' test entry keep their precise types: the doors' test entry still overrides doors and calls `super`. The interface is generated as method signatures, not a mapped type: tsc refuses a method that overrides a property (TS2425).
4. **The handler map is typed by the rows.** `owner-do.ts` holds `DoorName`, `Module`, `CallerOf<D>`, `GateOf<D>`, `HandlerOf<D, N>` and `DoorsOf<M, N>`, and `HANDLERS = Object.freeze({ files: filesDoors, … }) satisfies { readonly [M in Module]: DoorsOf<M, OwnerState> }`. tsc then refuses each of these:
   - a module a row names but the map lacks;
   - a module key no row names;
   - a missing handler;
   - a handler whose shape is not its row's gate (a `Call` handler on a `units` row, or the reverse);
   - a handler whose first parameter wants more than `N` gives. This is the contravariant check that B3's `DoorNeeds` rides (below).

   The static block also refuses a handler that no row of its module names. That check runs at module load; tsc cannot see it from a non-literal object. The runner's one cast, `as never`, is where the row's request meets its handler's type. The fields step holds the request at run time, and `HANDLERS` holds the handler to its row in tsc.
5. **`invoke` goes through the map** (d2 B3's line, built here because B4 makes it free). `OwnerState.invoke(door, binding, request)` calls `#call` with the row and handler. Code mode no longer calls `Reflect.apply` on a method name or passes `takesRequest` arrays. A test subclass's override is no longer on code mode's path; only the doors' test entry has one, and the recorders are identical.
6. **`HANDLERS` leaves the contract.** `DoorRow.handler` is a module's name, which `doorProblems` holds to a kebab-case word. The typed map holds it to a module the object builds. `contract/guards/doors.test.ts`'s `existsSync(owner/src/<handler>.ts)` goes, the contract's reach into the owner's file layout that list2 `o2:2i` names.
7. **The three checks of "the methods are the rows" become one.**
   - `owner/guards/door-methods.test.ts` is deleted.
   - `write-gate.test.ts`'s "hands each door its handler from the module its row names" is deleted. Its door half now reads handlers: every `units` row's handler begins in a unit of the state it is handed, and `#call` runs every other gate in a unit. Rows that take no binding are exempt, as the old method check exempted them.
   - `owner.test.ts`'s surface test stays, as the research's one test. It checks that the prototype's names, less `RPC_RESERVED`, are exactly the table's, so a public method written beside the loop fails. It reads the contract's list in place of its own copy. Its five absent wake names go: the equality covers them (list2 `2h`).
8. **Guards changed for the static block, each with its reason:**
   - The module-state rule refuses any static block, so `OwnerDO.static` is an exemption in `owner/guards/rules.ts` (`MODULE_STATE`), with its reason. The block runs once at load and keeps no state.
   - The contract's isolation rule bans the name `fetch`. Its entry now has one home, `contract/src/doors.ts`, which names it only as the first reserved RPC name.
   - The cutover manifest lists `owner/src/door-map.ts`, which loses its import rows when `npm run generate` runs after `contract/doors.json` loses them.
9. **Departures from d2 B4, and what is left:**
   - **Left to `untangle/o2b`:**
     - the split into `contract/doors.json` (what the doors speak) and `owner/doors.json` (the runner's steps);
     - `OwnerDoors` written by the generator from the contract half, with its tool descriptions;
     - the services guard's name and arity checks becoming type facts.

     That is the contract half. Built here, it would put this PR well past 1,500 changed lines. Until then `OwnerDoors` stays hand-written, and `implements OwnerDoors` still holds the doors' view against the handlers' answers.
   - **The doc comments:** each hand method's doc moved onto its handler, where the handler had none or only a one-line restatement. A doc that only repeated a handler's longer one went. A tool door's doc is also its row's description, on `DoorMethods`.
   - **Kept for B5 (O3):** the unbound doors' `undefined as unknown as Binding`, now in one place (the loop), not two. B5's binding kinds remove it.

## B3's shape (coordinator, from o1_research.md)

The coordinator's decision on B3, recorded before O1 builds it: B3 is built as `o1_research.md`'s refined option (b′). These lines of d2 are departed from, each for a better shape:

1. **Stores keep only their own state.** The classes `ownerStores` builds keep their constructors. A module joins `ownerStores` when its constructor takes only stores, units, env and id, and a test needs it (`Sessions`, `Keys`, `Registrations`, `Archive`). The object still builds, once, the modules tied to its Lifecycle, runner or launcher. **Departs from d2 B3, Design, bullet 2** (`untangle-2026-11-wave-2.md:130`): "a constructor taking `<Module>Needs` … Its door handlers take the module itself". A whole-reach constructor `Needs` would make `ownerStores`' four outside builders need stand-ins for the schedule, the runner and the launcher.
2. **A handler's reach is a static, per-module `<Module>DoorNeeds`.** It is a structural interface of the module's own store, the other modules' methods its handlers call, the units and the object reads. tsc checks it at the object's one record of its parts. The runner hands every handler that one plain frozen parts literal, and `const HANDLERS: { [M in Module]: DoorsOf<M, Parts> }` holds that the record satisfies every module's `DoorNeeds`, since parameters are contravariant. The row decides only which module's `DoorNeeds` applies (`row.handler`); no reach is listed in `doors.json`. The parameter stays `o`.
3. **Widening is four proofs, each required by the widening method itself.** The proofs are `LiveSession` (minted by `Sessions.live`, on the session rows' `Call` as `call.session`), `OwnerSelf` (the owner rows'), `PlatformLine` (the reserved rows') and `ImportLine` (the import rows'), declared in `door.ts`. Each widening method takes its proof as its first argument, so tsc refuses every caller that holds none, and N10 holds at run time through `LiveSession`. **Departs from d2 B3, the widening rule** (`:137`): "only the `Widen` capability … a module that widens receives `Widen`". One `Widen` would let the owner rows set a grant with no live session. That bullet's import-list half holds as written.
4. **The policy-boundary guard is cut to a no-forged-proof cast rule.** Its widening half goes (`STORES`, `ROOTS`, `WIDENS`, `OTHERS` and the `o` naming rules). A source check stays: no type assertion to a proof appears outside its minter (`sessions.ts` for `LiveSession`, `owner-do.ts` for the other three), since the brands are type-only and tsc does not refuse a cast. `MODULES`, the tables, the read-only export, the loader and the sandbox's spend stay. `ledger-boundary`'s `REACHERS`/`REACH` go.
5. **Runner facts go on the `Call` or become row steps:** the row step `seeded`, the tiers kept in `#bind` alone, and `call.scope` and `call.universeOf()`.
6. **O2 lands before O1.** **Departs from d2 B4's "Depends on B3"** (`:181`) and §D row O's "O2 after C2 and O1" (`:819`). O2 removes the hand methods O1 would otherwise edit, and its generated map types `Call<R, K>`. This PR ships what O1 reads:
   - `DoorsOf<M, N>`, generic in the handler's first parameter, so an unconverted module keeps `OwnerState` and a converted one names its `DoorNeeds`;
   - `CallerOf<D>` and `GateOf<D>`, from the generated `DoorRows`, so `Call<R, K>` takes `K = CallerOf<D>` in `HandlerOf`.

   O1 moves these types, with `Call` and `Door`, to `owner/src/door.ts`. `door-map.ts` imports nothing from `owner-do.ts`, so the layer row "no module but the entry imports `owner-do.ts`" holds for it. The row step `seeded` goes in `contract/doors.json` until `untangle/o2b` splits the table, then in `owner/doors.json`.
7. **The PRs:** `untangle/o1` (`door.ts`, placement into `Bodies`, `Archive` into `ownerStores`, `seeded`, tiers in `#bind`, `call.scope`, the leaf modules), `untangle/o1b` (the four proofs, the widening signatures, `tier.ts` into `admission.ts`, `Launcher.endClient`/`endAll`, the policy modules, the guard cut), `untangle/o1c` (files, collections, ledger, import) and `untangle/o1d` (runs and launch, signins, restore, `OwnerState` deleted, the layer row).
