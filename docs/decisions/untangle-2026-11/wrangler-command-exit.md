# Wrangler command completion as built (2026-11-18)

The platform test bundle, binding generator and deploy adapter resolve the CLI exported by the pinned platform package and run that file in Node. Wrangler 4.154.0's bin starts that same file in a child process and converts its signal exit to status zero. On Node 22 and 24, terminating the CLI before it could print its version reproduced the silent success. Direct invocation propagated SIGTERM. Both uninterrupted invocations printed 4.154.0. The repository already requires Node 22.18 or later.

The deploy adapter checks the subprocess result before continuing. Secret puts, first deploys, version activations and trigger changes use that result. A versions upload also checks its printed ID. An interrupted command can have taken effect remotely before it loses its reply. The operator must reconcile the affected step against live state before a retry. This change does not automatically repeat it.

The permanent regression runs the actual deploy adapter and interrupts a local version query on the published CLI before argument handling. The same test fails on main. Offline verification also covers ordinary numeric errors and successful builds. The separate store probe owns its classification of an interrupted command, and the legacy proxy workflow installs a separate Wrangler version. Review those consumers before using their evidence. No production command was run.

Three paired runs exercised the original deploy harness with synthetic provider I/O and the actual CLI exit. At the second secret put, third version activation and route-trigger step, the selected command ran a local interrupted version query in place of a provider call. Main accepted each zero exit. The fixed adapter stopped at the interrupted step in all three and issued no later Wrangler command or hook enable. For a trigger interruption, some route changes precede the trigger. Inspect those routes before handback or another attempt.
