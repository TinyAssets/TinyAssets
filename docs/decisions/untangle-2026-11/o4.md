# O4 as built (2026-11-15)

O4 is split at the fix boundary the brief names. This PR is B2's and B7's owner adoption, and empties the owner's `OWED` of both. B10's owner-test literals with B10's literal guard, and B6's owner adoption, are O4b (`untangle/o4b`, item 7).

1. **The owner's three error classes are contract refusals, told apart by code.**
   - `Conflict` (`collections.ts`) and `FileConflict` (`files.ts`) are `conflict` refusals whose facts carry `current`, the row or entry as stored. Each module throws its own (`conflict`, `fileConflict`) and reads it back in one place (`conflicted`; `files.ts` `lostSwap`, which the starter's two catches also use). The code was already the contract's (`policy.ts`, `import.ts` and `runs.ts` throw it), so no code is added.
   - A refusal without facts is not a lost swap, so another module's `conflict` thrown inside a write still reaches the caller.
   - The sync op's outcome no longer names the code by hand (`error instanceof FileConflict ? "conflict" : error.code`): it is the refusal's code, the same `conflict`.
   - `ParentMoved` (`ledger.ts`, `roomPost`) is `archive_changed`, the code the archive's own moves already retry on (`archive.ts`). The post reads its parent again on it, up to `READ_TRIES`, then answers `archiveMoving()` as before. `prepare` and `post` throw no `archive_changed`, so only the parent's move is read again.
   - Answers are unchanged: every product path catches the conflict and answers `{conflict}`. One path does not: the import's row write (`import.ts` `importRows`), whose row a second unit writes after a first found none. Two writers inside one import window would have thrown a plain `Error` (a bug, `500`); it is now a `conflict` refusal (`403`). The window is closed to every other writer, so no product request reaches it.
2. **B2's other owner call sites, in the same files:**
   - `NOT_GRANTED` is `not_granted` at the four sites that threw it as `refused` (`owner-do.ts` `#scope`, `#syncer`, `#runDoor`; `ledger.ts` `mailsAgent`), as `authority.ts` already threw it. Both codes are quiet `403`s, so every door answers the same bytes; only the code across RPC moves.
   - The three `storage_busy` messages lose their JSON (`{"retry_after_s":…}`). The wait was always the refusal's `retryAfter` (the code's `30`, or `archiveMoving`'s `1`), which the doors answer as `Retry-After`. `ledger-bounds.test.ts` read the wait out of the message; it reads `retryAfter` now.
   - `launch.ts`'s start answer is the contract's `Started`, not a restated type with `code: string` (`s7.md` item 6). `SANDBOX_WAITING` and `SIGNIN_REQUIRED` already came from the contract (S8).
3. **The refusal guard owes nothing now.** The owner held its last three entries. `ci/guards/refusals.test.ts` (lane C's file, one test) held that the tree still had breaks (`problems.length > 0`), which is false once the debt is paid. It now holds that the tree has none, with the sources read non-empty so the check is not vacuous. `ci/kit/owed.ts`'s `refusals()` (lane C's file) had no caller left and is deleted, so no workspace can owe the guard again without writing a new helper.
4. **B7's SHA-256: the owner's eight uses read `contract/src/digest.ts`.** The one-shot ones are `sha256` (the bloom bits, the manifest spread, the meter's execution id, the PKCE challenge). The PKCE verifier is base64url, so its UTF-8 bytes are its ASCII bytes and the challenge is the same. The five streamed ones (`archive`, `edit` ×2, `segments`' image digest) are `sha256Stream()`, the streaming form `c6.md` item 5 said the first adopter adds: one function in lane C's file, returning `node:crypto`'s `Hash`, which they already used. Lane S's two streamed hashes (`sandbox/runner/sync.ts`) can take it.
5. **B7's clock: `clock()` everywhere, and `clockMs()` beside it.** A departure from d2 B7's letter, from what the code needs:
   - 15 of the 43 reads were seconds (`Date.now() / 1000`), and are `clock()`.
   - 28 were milliseconds, and stay milliseconds: Lifecycle's job times and `rescheduleAt`, a manifest root's `at` (`contract/src/files.ts` `manifestLists` holds it `whole`), a credential's lease (`connections.lease_until`, stored), the meter's read time (stored), a pass's `until`, and four in-memory windows (`codemode`'s deadline, the control gate's freshness, the relay's held sign-outs, the erasure's last start).
   - `clock() * 1000` is `Date.now()` only while now is under 2³¹ seconds (2038-01-19). Past it, about half of all millisecond times do not round back to the same integer through the division and the multiplication (measured over 10⁷ samples each side), and a root's `at` would then fail its own check. So the kernel gives the same now in whole milliseconds too, `clockMs()`, and `clock()` is `clockMs() / 1000`, the same value as before. Every module still reads now from `clock.ts`, and the kernel guard holds it there.
   - No site changed its unit, so each swap is the same expression. Mutations, one per kind: a seconds site read as `clockMs()`, and a milliseconds site read as `clock()`, each failing its tests (the PR body lists them).
   - `collections.ts`'s private `now()`, a copy of the clock, is gone; its two callers read `clock()`.
6. **The kernel guard's owner counts are zero**: the owner's `OWED` keeps only B23's import entries.
7. **O4b (`untangle/o4b`), owed, in lane O's files:**
   - B10's owner-test literals (`owner/test/{files-quota,storage-full}.test.ts`, `owner/memory/probe.ts`), then B10's literal guard over every folder, with the sandbox's literals `s6.md` item 2 lists.
   - B6's owner adoption: signins (`signinUrls`), inbound, egress (`egress.ts` `HINT`, V2), the three range builders as one (`F-H3′`, V2), `sessions.ts` `ttlS` as `SESSION_TTL_S` (`d3.md` item 6), and `holds.ts`'s `API_BODY_MAX` as `EGRESS_BODY_MAX` (D1).
   - B7's remainder found here: the clocks the owner's constructors take (`Schedule`, `Connections`, `ErasureParts`, the starter's and the wakes' deps) are always `clock`, a seam only the tests vary. They read `clock()`, and their tests move a fake `Date`, as d3 §K2 has every other timed test do.
   - A lane's pass takes `now` in seconds and `until` in milliseconds (`schedule.ts` `Lane.run`). One unit, seconds, changes the seven lanes, `generation-support.ts`, `export.test.ts` and the memory probe, so it rides O4b with the probe's other change.
