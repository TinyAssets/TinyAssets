# X4 as built (2026-11-14)

X4 builds `d2` B13's routes and control record, as `d3` §J1 decided them from the research of 2026-11-12 (`research_b13_r6.md`). B13's sign-in half (`contract/src/signin.ts`, `connected` and the app's page paths in `identity.json`) is not in this PR.

1. **The doors take `app*` and `api*` in place.**
   - `identity.json` `routes` is `/mcp*`, `/api*`, `/app*`, `/hooks/inbound/*`, `/hooks/e2b/*`, `/authorize*`, `/oauth/*`, `/.well-known/oauth-*`.
   - The handover moves the old proxy's `api*` and `app*` to the doors in place (`PUT`), as it does `mcp*`. `/api/*` and `/app/api/*` go, since `api*` and `app*` take their URLs.
   - The old proxy is left with no route. `PROBE_ROUTES` is unchanged.
   - The deploy test's "`/app` stays the proxy's" flips: after the handover the proxy holds nothing, and `/app` and `/app?upgrade=1` are the doors'.
2. **One matcher.** `contract/src/identity.ts` `routeTakes` holds Cloudflare's matching:
   - it reads the whole URL, query included, never the fragment;
   - a pattern ending in `*` takes every URL it begins, any other only itself, and any other `*` throws.
   - `deploy/facts.ts` (`PROBE_ROUTES`), the identity guard and the deploy test's `servedBy` and hook check use it. The guard's private `takes` compared paths only, which is how it hid the query-string bug, and it goes.
3. **The identity guard checks every URL the app, the site and the shells use,** query strings included, against `routes`, each with its source:
   - `/app?upgrade=1`, `/app?request=…`, the sign-in's return, the old stack's returns;
   - and the site URLs no doors route may take.
   - `first_party.redirect` and `first_party.resource` join the identity paths it holds.
4. **The touch icon leaves the `app` prefix.**
   - `WebSite/site-react/public/apple-touch-icon.png` moves to `public/icons/apple-touch-icon.png`, byte for byte.
   - `layout.tsx` emits the new link. `render_marks.py` writes the new path, and `generated-assets.json` records it with the exporter's new hash.
   - `scripts/invariants/brand_parity.py` and the site's brand test name the new path.
   - The identity guard reads the site's public files and pages (`WebSite/site-react/public`, `app/`) and fails on any under a doors pattern, through `routeTakes`. Departing from d3 §J1's "site-side test", by review: a test in the site ran only in `deploy-site-react`, after a merge and only on a site change, so a site file under a doors pattern merged green, and a change to `routes` was never checked against the site at all. The guard runs on every PR, on either change, with the one matcher and no copy of it.
   - **Outside lane X:** the old stack's `scripts/probe_app_surface.py` checked on every `deploy-prod` that `/apple-touch-icon.png`, the one site file under the old proxy's `app*`, reached the website. With no site file under `app` left, that check witnesses nothing, so it goes (check 4 and its constant). The edit is a runtime input (`scripts/runtime_paths.py`), so the merge builds the image and runs `deploy-prod` once, behind its own idle-turn gate.
   - The root `/apple-touch-icon.png` is not kept: it is under `app*`, so after `routes` it is the doors' whatever the site holds. Every site page names the icon by its link. The doors' own pages (`doors/app/*.html`) name no icon, so iOS asks the root for theirs and gets the doors' 404; giving them a link is the doors lane's, owed.
5. **The control record.**

   - The probe's gate parses the record with `parseControl`, so a malformed record stops it as an open one does.
   - `admitsNobody` and its hand-table test go. The probe's stop is tested through the kit instead, on an owner-admitting, an all-admitting and a malformed record, each stopping with no route change.
6. **The kit's text.**
