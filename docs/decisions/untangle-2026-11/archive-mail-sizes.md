`budgets-ci-measure.md` §4 owed this retag to `untangle/archive-mail-sizes`.

1. **Every `archive-mail.test.ts` test that calls `seeded()` is `large`.** `seeded()` gives the ballast agent `maxUnacked - room` real messages at production's `LEDGER_LIMITS`. That is production sizes with real-size data, so the size rule in `ci/classes.ts` makes the test large, whatever its time. Thirteen such tests were still medium, and this PR tags them. The other eleven medium tests call no `seeded()` and stay medium. Seven are the record-format tests. The other four carry no ballast: a failing parent read and an aborted move, each on an owner holding at most one body; the export across a move, whose 4,000 messages of 2,000 bytes are just past one seal's worth (4.5 s in CI); and `TIER_STORAGE_MAX`, which reads no owner. `seeded()`'s doc now says that a test calling it is large, so the next test to call it is tagged with it.

After the move, the slowest owner test left in the medium tier is `restore.test.ts` at 11.4 s, which is under 38 s.
