# signin-probe-completeness as built (2026-11-18)

1. **The pair probe requires what the record says the CLI displays.** On `f934871ad` the probe waited for both a URL and a code when the record had `cli.login.code_pattern`. If the CLI exited first, its final verdict accepted the URL alone. The same check now decides when to stop the CLI and whether the output was complete. A wrong page still keeps its own refusal. An engine that accepts a code on stdin need not display a code.
2. **The kit uses the probe verdict.** Its pair check requires both the exit code and the JSON `ok`. A second copy of the record's code rule in the kit would let those two interpretations diverge again. In 21 offline cases on Node 22 and 24, the original packaged probe marked three incomplete prompts successful (Codex and both Kimi regions). The new probe rejected all three. Complete prompts, missing URLs, wrong pages and URL-only records kept their verdicts. The probe ran with synthetic child output and without a vendor process.
3. **Still open, separately, on `codex/untangle-signin-prompt-framing`.** The runtime and probe each interpret every stdout/stderr chunk as soon as it arrives. On the real record matchers, splitting the same synthetic complete output gave a premature URL refusal on all five engine/region configurations. It also yielded a shorter accepted URL for Claude, Gemini and Kimi. Codex and Kimi could retain only the first part of a displayed code. The standing evidence in `sandbox-probe.md` records hosts and code presence. It does not record the bytes that terminate each displayed field.
4. **Before changing the reader**, establish those delimiters from each pinned emitter's source or a sanitized offline output fixture, including a prompt waiting for input. Then give the runtime and probe one reader for completed values, with bounded memory, separate stream state, terminal escape handling and exact shape checks before release. Split each fixture at every byte and compare values and refusals to its complete output. A variable-length code at the end of a chunk can be either complete or a prefix. An assumed newline or a quiet timer would leave that ambiguous. This dependency concerns outgoing prompts. The owner's pasted input is a separate, length-bounded message with an explicit end.
