# R5 P-hooks as built (2026-11-21)

R5's fourth slice (d3 §N2, §N3; `r5_research.md` §2.1, §5.3, §6 slice 4), on P-decide (#5672, `r5-decide.md`) and P-resume (`r5-resume-hooks.md`). The research is the design; what it left open was researched first (Fact 14), from the vendors' own pages and code, read 2026-11-21: Claude Code's hooks and headless pages (code.claude.com/docs/en/hooks, /headless), Codex `rust-v0.166.0` (`codex-rs/hooks/src/engine/discovery.rs`, `events/pre_tool_use.rs`, `codex-rs/config/src/hook_config.rs`, `config_requirements.rs`, `codex-rs/core/src/tools/hook_names.rs`, `tools/handlers/mcp.rs`), Gemini CLI `v0.66.0` (`docs/hooks/reference.md`, `docs/hooks/index.md`), pi `1.4.0` (`docs/extensions.md`, `docs/mcp.md`, `docs/cli.md`) and Kimi Code `2.4.1`'s package. What follows is how it landed and where it departs.

1. **Departure: no engine defers; a held call is refused with its card on every CLI, Claude Code's too.** The research chose Claude's `defer` and, until §8.1's live check, a managed `permissions.ask` rule beside each `ask` act. The hooks page rules both out as the run is set up:
   - "Deny and ask rules are still evaluated regardless of what the hook returns." So with the paired `ask` rule, a `-p` run with `--permission-prompts none` denies the approved call too, on every resume: a yes could never admit it.
   - Without the pair, a turn of several tool calls ignores `defer` "and the tool proceeds through the normal permission flow", which in `--permission-mode auto` is the classifier: the held call can run.
   - So the fail-closed shape (Fact 8) is the one every CLI already has: the hook refuses the call with the card's reason, the run goes on or ends, and the owner's yes resumes the conversation on P-resume's message (`r5-resume-hooks.md` item 3), which the approval admits.
   - **Owed:** `r5-resume-hooks.md` items 6 and 7 (a deferred call resumes on no input; its conversation waits on its card) have no deferred call to act on. They come with `defer`, in `untangle/r5-defer`, only if d3 §N9's first live check (`live:` Claude `defer` with several tool calls in one turn) shows that turn denies. The `tool_deferred` matcher (P-resume) stays, and matches nothing until then.
2. **One answer shape, so a record carries no input paths or output templates.** Every CLI here hands its hook `tool_name` and `tool_input` on stdin, and each blocks on exit 2 with the reason on stderr (Claude's page, Codex's `pre_tool_use.rs`, Gemini's reference); pi's extension is the record's own template, which runs the same helper and blocks on any other exit. So the helper answers exit 0 and `{}` (no decision: the CLI's own flow goes on) or exit 2 and the door's reason, and a failure of its own is exit 2 too. The record's `decide` block (`sources/src/schema.ts` `Decide`) is where the config goes, its template, the CLI's names for each tool kind and for an MCP tool, and `fails`.
3. **A managed file is the sandbox's, not the run's.** Claude's `/etc/claude-code/managed-settings.json` and Codex's `/etc/codex/requirements.toml` are one path for every run, which the research did not weigh.
   - So the hook's matcher is the owner's rules' for every agent (`Actions.hookTools`), never the run's agent's alone. A sandbox is one authority's, so every run in it needs the same file at one policy generation, and the latest run's start writes it, or removes it when no rule names a tool. There is no per-run share and no lock.
   - The cost: a rule naming one agent makes another agent's matching call ask the door once, which lets it be (the decision holds each rule to its agent).
   - Every run of an engine with a hook carries its decide door (`TA_DECIDE`), so a hook a later start wrote decides a live run's calls under the live rules. Claude re-reads a settings file it watches; Codex reads its requirements at its start.
   - A run's own file (Gemini's system settings, merged into the record's file of that path; pi's extension, loaded by `-e`) is its start's: a rule added mid-run holds there from the agent's next run, and at the doors at once.
4. **Codex's requirements also pin `features.hooks = true`**, so no config the agent writes turns its hooks off. Managed hooks need no trust and can't be disabled from a user layer (`discovery.rs`).
5. **The helper is a command of the runner bundle (`decide`), so the pair check pins it.** The hook runs it as the run's user: `/usr/local/bin/node /opt/ta/runner/<digest>/runner.mjs decide`, the loader's node and the runner's own bytes (0644). It is runner protocol 2: protocol 1's commands but its retired ones, and `decide`; its documents and answers unchanged, so the Worker writes and reads the same.
   - **Two deploys** (`protocol.ts`): the expand, a Worker that speaks 1 and 2 with protocol 1's runner, is `untangle/r5-hooks-speaks`, which lands and deploys first. This branch's runner speaks 2.
6. **The start asks first, then checks.** The root runner asks the run's decide door which tools the hook matches (`check`) before it makes the run's files, and writes the hook only for those. Where it wrote one, the helper runs once as the run's user, in the CLI's environment, before the CLI starts. A failure fails the run loudly (`ta.runner_error`), which closes Codex's and Gemini's fail-open at the start; mid-run it stays open there (`fails: open`).
   - A run of an engine with a hook asks once even when no rule names a tool: one Worker and one object request a run, none a tool call.
   - The decide door's URL is the run's own path beside its MCP door (`contract/src/egress.ts` `decideUrl`), so the start document names no new URL and nothing new enters the VM (research §8.8): the run's secret is already its CLI's.
7. **What a call is.** Each act whose hook kinds name the tool (`acts.json`, the record's `kinds`), or one of whose rules names it (`tools`), decided as that act's door call is (`Actions.decide`), the strictest rule's act first; the card's door is the tool's name and its request the tool's input.
   - A `tools` matcher's characters other than a letter, a digit or `_` match any one character, because each CLI rewrites them in its MCP tool names its own way (pi: every one to `_`). The pattern holds every name a CLI may give the tool, never fewer.
8. **Kimi holds no hook (`unsupported`).** Kimi Code 2.4.1 runs `PreToolUse` hooks, but its bundle names no root-owned path they load from, so a hook there is the agent's to edit. A rule holds on Kimi at the platform's doors alone.
9. **Not built: the research's second line of static denies** (`permissions.deny`, `prefix_rule`, an admin policy) from the same data. The hook refuses a `never` already, and a static rule's vocabulary (`Bash(curl *)`) is one no rule here writes.
10. **The honest note (d3 §N5): the policy's projection answers, beside each rule, where it holds and where it can't (`Actions.ruleNotes`),** so `policyRead` and the write's own answer carry it alike. It holds at `doors` (the platform's tools and doors that do its act) and at each engine whose hook sees it, by its kinds or the rule's tools. It can't where `acts.json` says nothing of ours sees the act (`unseen`), at an engine whose CLI holds no hook for it, nor, mid-run, at a hook that fails open (`<engine>.fails_open`).
    - **Departure: every engine is named, not the agent's alone.** An agent's engine is `auto` (the strongest connected source, Direction 4) or its own `agent.json` to change, so a note held to one engine would go stale with no rule changed. The owner reads where each engine holds it.
11. **The decide door is outside-callable by its caller (`account`), so the owner's door guard lists it among the doors the doors call themselves** (`owner/guards/doors.test.ts` `DOORS_ONLY`): only the egress host's decide path calls it, by the run's own secret, and its handler refuses every account but a run's.
12. **Owed live checks** (d3 §N9, at the dark redeploy; `live:`): Claude's managed file against an org's server-managed settings; Codex loading `/etc/codex/requirements.toml` under a run-local `CODEX_HOME`; Gemini's system-settings hooks under `--approval-mode yolo`, and whether a project layer can drop them; pi's `-e` in `--mode json`; the delay one decision adds.
