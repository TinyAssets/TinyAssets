# b24-dry-run as built (2026-11-21)

`untangle/b24-dry-run` is the merge plan's item 6, second of two PRs. It builds B24's dry run (d3 §A10) and step 5's "dry run green". It also closes B12's reshape of the modes that stay and §9 step 15's structural guards, and fixes the two items #5703's review left. Research came first (Fact 14): a prototype applied the manifest to a scratch checkout, and every suite ran there before the design was chosen.

1. **What a dry run can apply: the deletes and the carry-outs, never an edit.**
   - An edit is a list of names, not text, and a move into a file that stays re-points its importers. Both are the cutover's to write, so the dry run makes neither.
   - It makes the rest of the cutover in the checkout it runs in (`ci/kit/cutover.ts` `dryRun`, run by `ci/dry-run.ts apply`):
     - each carry-out (a whole-file move out of a deleted path) is moved, then every tracked file the manifest deletes is removed;
     - what an edit still loads stays, with whatever that loads in turn. The edit is unwritten, so its file still needs them;
     - each test file an edit names is set aside. An edited test is the cutover's to rewrite, and a test is what a suite runs, never what another file loads;
     - npm installs no workspace without its manifest. So each workspace whose `package.json` goes leaves `platform/package.json`, and npm rewrites the lock (`npm install --package-lock-only`, offline in under a second).
   - The claim it proves: **nothing that stays, and is no edit, needs what goes.** The prototype found that the alternatives fail. A deletes-only tree fails the typecheck at every edit's import. Keeping in-place moves breaks their importers. A tree outside git fails the guards that list files with git. Running edited tests fails them on their own unwritten edits, such as `environment.test.ts`'s and `legs.test.ts`'s lists.
   - Setting aside a whole file, and not only its failing cases, is the price of one rule for every runner (vitest, node, pytest). Fourteen test files are set aside. The static guard holds what each edit names, and the cutover PR's own CI runs their rewrites.
2. **The job is `cutover-dry-run.yml`**: on every pull request, nightly and by hand. No job holds a secret, nothing is pushed, nothing live is reached.
   - Its legs are `platform-tests`' own (`ci/dry-run.ts legs` reads `tests.yml`), less each workspace the manifest deletes (`import`). A new leg needs no second edit.
   - A `checks` job runs the typecheck and the process leg (`scripts/tests`, carry-outs included).
   - It was not required: a required job would add a full suite run to every queue entry. Corrected by `dry-run-required.md`: `tests.yml`'s `required-tests` needs it on every event but the merge group.
   - No actionlint: a deletion changes no staying workflow's text. What it can break there, a local action or a script a step runs, is a path the scope rule (item 4) holds on every PR. actionlint stays `actionlint.yml`'s, so its version and checksum are not copied.
   - **Green locally on this head:** the typecheck, all 13 legs and the process leg pass on the tree (body, "Gates"). This PR's own run is the live proof.

7. **The manifest's names are anchored to code, not prose** (the coordinator's finding from #5704).
   - An edit's names couple the manifest to other files' text, and #5704's comments pass broke two prose names.
   - 33 prose names are re-anchored to the path or identifier their text cites, such as `scripts/deployed_sha.py` for executable-gates' row, or dropped where another name already anchors the same text. Where the text cites nothing else, the shortest phrase stays: the founder's setup's comment mentions and host-actions' setup rows, `**retiring stack**`, `on-disk catalog` and `cutover's import`.
   - Code fragments stay: step names, imports, test titles, YAML keys. They change only with the code, and then the manifest should change too.
   - No mechanical rule is added. "Prose" cannot be told from a code string by a pattern, and a rule that refused whitespace would refuse every step name and import. The rule is in the manifest's `about` and `cutover.ts`'s `Entry` note, for a reviewer to hold.
8. **A script a workflow's step runs is that workflow's load** (after #5708, `Cutover dry run` run 44883223962).

A declared workflow import counts as made where a step runs it. Nothing is special to the one test.
