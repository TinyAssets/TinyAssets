# b24-manifest as built (2026-11-21)

`untangle/b24-manifest` is the merge plan's item 6, first of two PRs: step 3's inventory, B24's manifest, and B12's end-of-hold list (d3 §A5, §A10, §H). It extends `platform/cutover.json` and its guard; it builds no second list. The dry-run job is `untangle/b24-dry-run`.

1. **The inventory is the manifest, every tracked path classified.** Each root of the tree was read for what runs it: the workflows, the scripts, the tests, `package.json`, the skills, the specs and the docs. A path goes when only the old stack, its workflows, its tests or its runbooks read it; a staying file that names what goes is an edit. A path under no entry stays. The manifest has 454 entries: 287 deletes, 103 edits, 12 moves and 52 live objects.
   - **Whole roots go:** `tinyassets/`, root `deploy/`, `Dockerfile`, `.dockerignore`, `docker/`, `packaging/`, `tests/`, `openspec/specs/` (its `config.yaml` already says so), and the old stack's leftovers `archive/`, `branches/`, `goals/`, `nodes/`, `data/`, `drafts/`, `pages/` and `knowledge/`. A whole root takes the entries #5685 and #5689 listed inside it: `tinyassets/desktop/icon_gen.py`, `tests/test_platform_setup.py`, the edit of `tests/test_workflow_production_environment.py` and the edit of `openspec/specs/public-website-surface/spec.md`. The site's requirements are held by its own tests (`WebSite/site-react/scripts`). `.github/test-durations.json` is now deleted whole, not edited.
   - **Per file:** 32 workflows (one in `routes`, three at the hold's end) and two actions, and 108 scripts (three at the hold's end). Each script is old-stack when only the old stack runs it, or it is one of the old suite's gates (`affected_tests.py`, `ci_required_tests.py`, `ci_structural_guards.py`, `ci_assert_junit_case.py`, `check_shapes.py`, `linux_oracle.py`, `prepare_oracle_runsc.py`, `refresh_test_durations.py`, `quarantine_oracle.py`), whose `tests.yml` jobs §9 step 15 deletes. `deployed_sha.py` goes too: it reads the old daemon's deployed sha. The kit's own run names the commit it deploys. Also per file: the docs of the old host (`docs/audits/`, `docs/concerns/`, `docs/getting-started/`, three of `docs/reference/` and 16 of `docs/ops/`), the 85 old OpenSpec changes and their archive. `untangle/p9-openspec` deletes those first and takes their entries out, and the guard's "every entry exists" makes it.
   - **Stays, and why:** `platform/`, the process scripts and their tests, and the skills' tools (`peer_agent.py`, `claude_chat.py`, `chatgpt_chat.py`, `lead_browser.py`, `browser_lock.py`, `tab_watchdog.py`, `user_sim_auth_hook.py`); the site, the shells (`mobile/`, `desktop-app/` and their workflows, docs and `assets/`, which F1 reworks after the cutover, §10 step 19), `ideas/` (p9-now kept it), `templates/`, `output/` (the ui-test skill's log), the ADRs and decision logs (history, never edited but their Status line), `provider_context_feed.py` (it goes with `development-coordination-runtime`'s decision, p9-now item 2) and `store-probe.yml` with its probes. A platform comment that cites the Python it was ported from, at a commit, stays true as history; B26's path check must read such a citation as history.
2. **The phases follow what a handback needs.** Between `routes` and the hold's end, a failed verify hands back, and the old stack restarts on its untouched volumes (`checklist.md`, the handback's steps 1 to 3). So a handback's restart, its canary and what they run stay until the hold ends: `restart-daemon.yml` (less its converge step, which reads `deploy/`), `retire_cheat_loop_deploy_fence.py`, `handles-canary.yml`, `mcp_public_canary.py` with `_canary_common.py`, `cloud-daemon-restart.md`, the droplet and its three SSH secrets, `TINYASSETS_WIKI_CANARY_TOKEN`, the box store's volume and the daemon image. The hold phase also takes the old proxy Worker, its Access token, the tunnel, the `mcp.` record, the Spaces backup bucket and `dns-canary.yml`. Everything else of the old stack goes at the cutover, its secrets with it. `routes` gains R1, `deploy-worker.yml` deleted (§9 step 12, d3 §J1). `tests/test_handles_canary.py` leaves with `tests/` at the cutover, a phase earlier: after the cutover nothing runs the old suite.
3. **A carry-out is a move from inside what goes, made before the deletes** (d3 §A10 names carry-outs). The guard took any entry inside a deleted path as an error, so no carry-out could be listed. Now only a delete or an edit inside one is, and a move into one is. Two kinds are listed:
   - the process tests under `tests/`: the five the `process` leg runs, and `test_skip_metadata.py` and `test_test_shape.py`, which hold `test_hygiene_gate.py` and which only the old suite runs today. Each moves to `scripts/tests/`, its root path one level deeper. `legs.test.ts` and `tests.yml` lose the paths. P6 ("the scripts' tests beside them") may move them first and then take these entries out;
   - `peer_agent.py`'s one import of the old stack, `subprocess_env_without_api_keys` with `API_KEY_PROVIDER_ENV_VARS`, carried into `scripts/peer_agent.py`. Without it, the peer-agents skill would break at the cutover.
4. **An edit is once a phase, not once overall.** B12's end-of-hold list edits `deploy.ts`, `deploy.test.ts`, `platform-deploy.yml` and `checklist.md`, which the cutover phase edits too. The guard counted an edit twice across phases, so these entries would have failed. The cutover layer kept one edit's imports a file (the last), so the hold edit of `deploy.ts` hid its cutover edit's import of `import-message.ts`; it now takes every phase's. The live kinds gain `tunnel`, `record` (a route record in the control namespace), `volume`, `image` and `webhook` (Stripe's endpoint), each named by an entry.
