# S9 as built (2026-11-14)

1. **S13's `lease_id` half (d3 §L5, which calls it "S8"): the parameter goes.** The sandbox `cancel` takes `{ run }` alone, in the contract, the Worker's entrypoint, `SandboxControl` and the owner's call.
   - A cancel acts on one run, never on a lease. The Worker finds the sandbox the run was launched in by its `launched` row (keyed by run) and has the runner stop that run's job, by its id. No other run and no lease is touched, so there is no stale lease that a check could keep from cancelling a newer one.
   - The owner's object is the only caller and the record of which runs are over. It sends a cancel only once it has decided a run ends (the owner's or a client's cancel, a grant change or revoke, a lost runner, a start with no answer), and settles the run whatever the answer is. Checking the lease in the Worker would copy the owner's run-to-lease record there, and could only make such a cancel miss, leaving the CLI running.
