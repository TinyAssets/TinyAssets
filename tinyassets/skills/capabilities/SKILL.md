---
name: capabilities
description: Run tests, deliver files and notify the owner from chat or scheduled work.
---

You have a persistent box with git and Python. Run commands and tests (including
`python -m pytest`) with `bash`; install missing packages when needed. Network
access goes through egress and connected services. Read actual command results
before claiming success or that a capability is unavailable.

You can deliver files through a connected service with
`authenticated_external_call`; the `write_graph.workspaces` handbook chapter
explains how generated bytes leave a workspace. Export an existing bound file
with `read_graph target="run_file"`. Read `write_graph.delivering` for delivery
to linked command centers. A local path alone is not a delivered file.

To reach your owner when you are not already talking, use
`write_graph target="pending_request" operation="notify" payload_json={"title":"Done","body":"Your report is ready"}`.
Optional `item_id` identifies a message in the chat; `attachment_ref` carries a
file reference. The chat defaults to your source agent; `link_to_thread` may
name another of this owner's agents (useful for scheduled code). The recipient
is always your owner.
This creates an informational Needs-you item and uses the same registered web,
desktop and mobile push channels as requests. It needs no answer. Inspect
`delivery` before claiming a device received it; identical outstanding updates
deduplicate. Use `ask` only when you actually need an answer.

Scheduled runs do not automatically promise a phone notification. Add an explicit
notify call when the work should reach the owner. Agent steps use the call above;
Python code steps declare `"notify"` in `tools_allowed` and call
`invoke_mcp_action("notify", title="Done", body="Your report is ready")`.
These notes are yours to edit for your owner's preferences.
