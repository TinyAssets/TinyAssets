# Native replies in an existing room

Use the existing owner event automation and native agent node. Do not add a server, global dispatcher, credentials, or another native agent. The scripts build a private workflow snapshot; they do not install or activate anything.

Read the actual source room workflow and canonical room adapter first. Verify the owner, command center and workflow identifiers with current owner-scoped reads. The adapter is trusted owner code and must provide `Room(home)` with `root`, `load()` and idempotent `post(data, participant, source, reply)` plus `safe`, `locked`, `atomic`, and `canonical` helpers. Its storage must reject links, fsync and atomically replace writes, serialize room mutations, preserve immutable source messages, and deduplicate participant/client_message_id while refusing changed content. Replies remain owner-relayed attribution. Never use a participant label as authentication. A successful new root-post receipt must contain `ok=True`, the canonical `room_id`, message `id`, `saved=True`, `duplicate=False`, and `operation="post"`; duplicate or reply receipts must report their actual operation and duplicate state.

`scripts/build_workflow.py` accepts a JSON config containing `author`, `command_center_id`, `storage_workflow_id` and `room_id`, plus a Python room-adapter source file. It embeds that adapter and the dispatch scripts into the owner workflow. Keep resulting snapshots private because they contain owner identifiers and code. The graph reads the actual completed source run and bounded receipt before reserving a durable claim. A native prompt node uses the existing `main` agent and only the `read` capability; deterministic code commits its actual output.

The claim is persisted before generation. Replayed in-flight/uncertain generations stop for owner review. A result persisted before a failed post is reused with its stable client message ID. Each source owner root post must explicitly address `village_elder`; introductions, replies, duplicates and unaddressed posts do not generate. Replies request nobody and disable follow-up. Unknown routes stop. The native node has no retry. Its runtime limit comes from the owner's served `absolute_cap_s` configuration; an ordinary node timeout does not bound a native turn. With no configured cap, the engine treats the turn as unbounded. Inspect the effective owner cap before activation; this workflow provides no 120-second guarantee. Existing engine interrupted runs are terminal; restart at the claim guard, never resume directly at the native node.

After code installation is approved, create the private workflow only. Separately approved activation must configure its owner-local `Dispatch.configure(enabled=True, max_total=1, max_daily=1)` and create one `run_completed` automation filtered to the exact source workflow and `outcome=completed`, with overlap disabled. Do not activate from this skill invocation unless the user explicitly authorizes it. Disabled is the default. Disabling through `configure(enabled=False)` revokes queued/in-flight claims; pausing the automation alone stops future wakes but does not revoke work already claimed. Keep both controls available to the owner. Never reset consumed allowances by deleting the ledger.

One native turn can make multiple provider requests. The total/daily turn limits and any configured owner runtime cap are not a dollar cap. Existing provider admission and budget controls apply; inspect the selected source and those controls before estimating cost or requesting paid activation. Native nodes use their normal owner context and read access; other participants can put prompt-injection text in the room excerpt. Actual replies are posted to the shared room without per-reply owner review, so activation accepts a disclosure risk for owner context the model can access. Do not claim the model sees only room history. The explicit room excerpt is bounded to ten messages and no native conversation is copied into storage by these scripts.

Before activation, test with a fixture provider: addressing, concurrent duplicate delivery, uncertain generation, crash after result save, crash after room post, revocation, missing/deleted room, bad receipts, exhausted limits and reply-loop suppression. Confirm current owner admission at workflow and tool boundaries. An installed workflow is not proof of a live response roundtrip.
